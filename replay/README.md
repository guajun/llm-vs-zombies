# replay

首版支持**状态复盘与实验材料归档**，不修改游戏进程，也不是 AvZ 的 `AReplay` 存档播放器。

`lvz export <run>` 将事件与元数据嵌入独立 HTML，离线打开即可播放/拖动采样状态。画面使用简化图形，位置为示意。每个采样之间的事件会展示；时间推进按 100 tick/游戏秒计算，跨 segment 单独衔接。

## 一次实验的目录

```text
manifest.json       身份、来源、规则、状态、能力标记、封存哈希
config.json         当次配置的冻结副本
events.jsonl        原生记录器或合成演示记录器（单写者）
inputs/             参考存档、本项目实现源码 ZIP、输入等材料
observations/       真正发送给模型的观察
decisions/          模型请求、响应与动作计划
checkpoints/        实际游戏快照，须另附恢复能力说明
video/              后续视频流录制的文件
summary.json        封存后的摘要
exports/review.html 可重建的复盘页面
```

`finalize` 在记录器关闭后执行，校验 JSONL 顺序并计算事件、配置和材料文件哈希；`validate` 检测文件更改、截断、错误 run_id、序号跳变及同一 segment 时间倒退。

目录中有一个参考 `.dat` 并不代表本次游戏实际从它启动。manifest 的 `initial_state.captured` 默认是 false。正式实验需记录加载过程、实际场景与起点，并附入实际快照。

## 下一阶段：原版引擎重放

设计详见[原版确定性重放器提案](../docs/原版确定性重放器提案.md)和[LLM 交互控制设计](../docs/LLM交互控制设计.md)，以下均为待实现能力。

1. 从可验证的初始化流程建立基线，定位 RNG、时钟及脚本状态；不假定普通存档能恢复全部状态。
2. 统一动作入口，记录帧号及帧内序号；暂停等待 LLM 时不推进游戏。
3. 回放时关闭原策略与 LLM，执行记录的动作。
4. 比较相同采样时刻的规范化状态并报告第一处分叉。
5. 补齐生成事件、特殊场地、投射物等字段，再扩充检查点。

`compare` 目前只比较日志的 state payload。它能检查记录字段一致，不能作为完整确定性的证明。

流式视频可按每 4 tick 取一张已渲染画面、送 FFmpeg 生成 25 fps 文件。现阶段只预留 `video/` 归档入口，不会把鼠标窗口截图伪装成逐帧、游戏时间同步的录像。
