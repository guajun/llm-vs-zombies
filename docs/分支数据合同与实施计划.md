# 分支数据合同与实施计划

日期：2026-09-22。状态：**已定稿，随 #29 合入 main**。本文提出合同、机制选择与 issue 划分，不修改任何既有实验结论，也不提升任何已声明能力。

## 0. 背景与需求

需求原文整理：可重放框架要产出有明确训练价值的数据，其核心性质是**轨迹只随模型输出的动作变化**。数据集包含不同最初起点的轨迹；不同起点之间即使动作一致也不要求轨迹一致（等价于不同 seed）。

由此推出三条可判定的性质（§1.1）。与旧框架的差别在于：旧框架把"全局冷启动逐字节等价"当作数据生成的前置条件；新合同把它降为**证据属性**，把"同源分叉决定论"提为主合同。

| 旧框架 | 新合同 |
|---|---|
| 确定性 = 枚举完整状态 + 冷启动逐帧等价 | P1 同源一致性（机制）+ 裁判（验证） |
| 从起点重算，检查点排在最后 | 分叉是主能力，从起点重算是基准 |
| 单一门槛覆盖全部用途 | 训练数据管线与计分运行管线分离 |
| 按层分类失效 | 按机制读取点分类失效 |

## 1. 合同

### 1.1 三条性质

| 名称 | 内容 | 判据 |
|---|---|---|
| **P1 同源分叉决定论** | 同一根 + 同一动作序列 ⇒ 逐帧相同的轨迹 | 训练数据必需 |
| **P2 根一致性** | 根必须是引擎的合法状态（引用完整、代次不冲突），且采样自真实对局分布 | 根准入 |
| **P3 跨树独立** | 不同根的轨迹不互相比较 | 数据集结构 |

原讨论中的 P2c（引擎未被修改）已放弃：本项目运行在 AvZ 接管下，原版逐位保真不是本数据集的要求。P2b 由"根逐字节等于某个真实时刻"降级为"根是一致状态 + 来自真实分布"。

注意 P2 只对树根成立。一旦离开主干，之后的节点都是反事实的，没有 ground truth，只剩 P1 可查。这一分工必须写进证据格式：主干节点可标记"有真实续跑基准"，分支节点不可以。

### 1.2 术语

| 术语 | 含义 |
|---|---|
| 根 root | 一棵树全部分支共享的初始状态（镜像或等价物）及其身份 |
| 节点 node | 一次决策边界上的状态；由 (父节点, 动作) 决定 |
| 边 edge | 一次语义动作及其执行边界（含推进预算） |
| 树 tree | 同一根下的全部节点与边 |
| S | 转移函数的输入集合，不是"全部内存" |
| 机制读取点 | 游戏机制读取某个量的位置，单位为 (字段, 读取点) |
| 三档结论 | 进 S / 可归一化为身份 / 不进 S |
| 恢复阶梯 R0–R4 | 见 §3.3 |
| arena | 生产用的分叉执行环境（本计划取进程级） |
| 裁判 | 逐帧审计与首分叉定位，用于验证而非驱动 |

### 1.3 两条管线必须分开

| | 训练数据管线 | 计分运行管线 |
|---|---|---|
| 分叉 | 必需（一棵树多分支） | 禁止（单主干） |
| 读档 / 接管 | 允许，作为建树手段 | 禁止，且须在证据里证明未发生 |
| 冷启动门槛 | 配置级一次 + 抽样自检 | 每次运行严格 |
| 证据 | 树 + 哈希链 + 抽样审计 | 完整逐帧审计 + 封包 |
| 对应 issue | #6 / #7 重写后 | #26 / #28 保留 |

两条管线共用控制面、审计与身份实现，但**门槛定义必须分开写**。否则"禁止读档"与"分叉是核心能力"会持续互相打架。

### 1.4 示例：一棵两分支树

以雾夜两仪为例，一段真实主干与两个分支：

| 项 | 内容 |
|---|---|
| 根 root | 加载参考存档并应用固定配方（seed、clock anchor、浮点模式）后的 B(3000)；身份 =（游戏 / 资源 / 存档 / DLL 摘要，初始化配方，镜像摘要） |
| 主干 | B(0) 到 B(3000) 的动作序列，真实续跑过，因此标记"有真实续跑基准" |
| 边 e1 | t=3000：policy A 输出 `plant(8, 2, 5)` + `advance 20` |
| 边 e2 | t=3000：policy B 输出 `plant(7, 2, 5)` + `advance 20` |
| 节点 n1 / n2 | 两条边各自到达 B(3020)，分属 branch_id=A 与 branch_id=B |
| P1 断言 | 若 A 与 B 输出相同动作，则 n1 与 n2 的规范化状态逐帧相同 |
| P3 断言 | n1 与另一棵树的节点不比较 |

术语在此例中的用法：

- "同源"指共享 root 与主干前缀，不指时间上同时发生。
- 一旦 e1 与 e2 不同，n1 与 n2 之后的轨迹不再互相可对齐；两者都不再是原版 ground truth。
- 主干节点可标记"有真实续跑基准"；分支节点不可，因为不存在"原版会怎么走"的对照。

## 2. S 的定义与裁剪

### 2.1 判据

一个量进 S 当且仅当它参与以下之一：

1. **比较 / 选择**：次序、阈值、坐标大小、状态分派
2. **算术**：位置、速度、计时器、浮点精度与舍入
3. **随机消费**：任何改变 RNG 调用次数或顺序的东西（含表现层对象创建、设备状态查询）

只用于寻址、查找、显示、日志的量不进 S——无论它多底层。典型对照：对象指针被解引用时是身份（数值无关），被用作播种因子时是值（粒子抖动完全由地址决定）。

### 2.2 分析单位是 (字段, 读取点)

同一字段在不同读取点可以扮演不同角色，因此分类必须落在读取点上，不能按字段名分类。

| 例子 | 作为身份 | 作为值 |
|---|---|---|
| 对象指针 / 句柄 | 查找对象；数值可归一化 | 用作随机种子时数值决定结果 |
| `DataArray` 槽位编号 | 哪一棵植物 | `IteratePlants` 按编号升序，同格冲突时小编号先被处理 |
| `mNextKey` 代次计数器 | 已发出的 handle 位模式无关 | 计数器本身进 S：它决定新 ID 是否会与旧引用撞车（机制成立，后果待实测） |

### 2.3 边界选择

P1 的失效全部来自跨边界输入。边界越大，残差越小，代价越高：

| 边界 | 状态完整性 | 时间可回退 | 设备状态 | 单分支成本 | 并行密度 |
|---|---|---|---|---|---|
| 进程 | 私有可写页 | 否 | 否 | 十 ms 级 | 高 |
| 整机 VM | 全部 guest 状态 | 是 | 是 | 百 ms ~ 秒级 | 低 |
| 全硬件模拟 | 全部机器状态 | 是 | 是 | 最慢 | 低 |

结论：**arena 取进程级，VM 只做配置级证伪**（§3.4）。VM 的价值不是跑量，是一次性把"哪些跨界输入真的影响动力学"从未知变成已知。

## 3. arena：a2 优先

### 3.1 候选

| 方案 | 分叉成本 | 并行 | 实现难度 | 主要风险 |
|---|---|---|---|---|
| a1 进程内自抓自恢 | 十 ms 级 | 串行 | 高 | 恢复者活在被恢复的内存里 |
| **a2 外部抓取 / 恢复** | 十 ms 级（略慢） | 串行 | 中 | 目标须全程挂起 |
| b `RtlCloneUserProcess` | µs ~ ms（COW） | 真并行 | 中 | 未公开 API、设备与句柄共享 |
| c 从起点重算（现状） | 分钟级 | 真并行 | 无 | 无（作基准） |

选择顺序：先 a2，再在需要并行时评估 b，c 始终保留为基准。

a2 相对 a1 的关键优势是**恢复者天生不在被恢复的内存里**，因此不需要就"恢复代码、栈、快照缓冲都不被覆盖"设计自包含 stub。b 的三个坑：未公开 API（跨版本行为待实测，线程复制语义尤其）、继承的窗口与设备句柄被两个进程共享、以及"要跑干净必须先把设备依赖砍掉"。

### 3.2 a2 路径

1. 只在控制器暂停边界执行（无 in-flight 请求）
2. 宿主侧挂起目标进程全部线程
3. `VirtualQuery` 枚举区间：抓取已提交、可写、私有，且不属于快照缓冲与编排程序的页
4. 记录各线程上下文与浮点环境
5. 恢复：改保护 + 写回 + `SetThreadContext` + 恢复浮点环境 + 恢复线程
6. 自检：恢复后立即重抓一次，与原镜像逐字节比较（R0）
7. 复用 launcher 已有的"挂起创建 + 注入"能力，方向相反

不采用 `GetWriteWatch` 做增量：它只对以 `MEM_WRITE_WATCH` 分配的区间生效，对已存在进程的内存不适用。增量只能靠写保护加异常捕获，首版不做。

恢复本身不要求静止边界——挂起时抓到的是真实机器状态，恢复后可继续执行；只有"决策点"才需要边界语义。

### 3.3 恢复阶梯 R0–R4

| 级 | 做法 | 失败指向 |
|---|---|---|
| R0 | 恢复后立即重抓，逐字节等于原镜像 | 恢复不是恒等变换 |
| R1 | 恢复后不推进，审计状态等于连续运行同刻 | 抓取 / 恢复范围 |
| R2 | 恢复后推进 1 tick | 环境差异首次被读取 |
| R3 | 恢复后推进 N tick | 慢速耦合 |
| R4 | 改恢复间隔、主机负载、并行度后仍等价 | 时间与共享资源 |

命名提醒：[#24](https://github.com/guajun/llm-vs-zombies/issues/24) 使用 L0/L1/L2 表示可重复性分层，与本阶梯同名不同义。建议可重复性分层改称"形态层 / 转移层 / 表现层"，本阶梯保留 R0–R4。

### 3.4 残余耦合清单

进程级边界下必须逐条固定或证伪的输入：

1. 时间源：`GetTickCount` / `QPC` / `time`
2. 音频设备状态：`IsPlaying` 等查询的返回值进控制流（#12 已实测）
3. 绘制调用：写回动画字段，属转移函数的一部分（#10 已实测）
4. 光标、焦点、窗口消息
5. 文件与日志游标、CRT `FILE*` 缓冲
6. 并行时的共享设备、用户档与目录

前三条已有实测证据，其余需按 N6 的探针逐条给出"已固定 / 已证伪 / 待定"。

### N1 分支数据合同：根、树、S 的定义与判据

目标：把 §1 与 §2 定稿成正式合同，替换旧框架的入口表述。
交付：本文档定稿；术语表；三条性质的可判定表述；两条管线的门槛表。
验收：用一棵两分支树演示术语无歧义；P1/P2/P3 各自给出可执行的判定步骤。
不做：不改代码。
规模：S。

### N2 机制读取点表

目标：从反编译源码逐子系统列出 (字段, 读取点)，作为 S 的唯一权威来源。
交付：人读文档 + 机器可读 JSON；每条含"值还是身份""何时读""后果""三档结论"。
验收：栈位、波表、`mNextKey`、动画时钟、FPU 控制字至少各有一条完整条目，并给出源码位置。
不做：不做实验，纯源码取证。
规模：M。

### N3 树状证据与身份

目标：让树成为一等公民。
交付：manifest / trajectory 增加 `root`（身份与摘要）、`parent`（父节点与边界坐标）、`branch_id`、轨迹哈希链；旧格式仍可读。
验收：一棵两分支树可完整封装、校验、导出；主干节点可标记"有真实续跑基准"。
不做：不改运行时。
规模：M。

### N4 分支作用域隔离

目标：防止 fork 出的兄弟用父进程缓存回答自己未执行过的请求。
交付：去重域与版本命名空间按分支隔离；跨分支 ID 冲突返回明确错误码。
验收：两个兄弟注入相同 `request_id` 得到各自结果。
依赖：N3。
规模：M（含原生改动）。

### N5 a2 外部快照 / 恢复 PoC 与 R0 自检

目标：拿到可用的镜像分叉能力。
交付：宿主侧挂起 / 抓取 / 恢复实现；R0 自检；报告抓取体积与单次耗时。
验收：先在无游戏的原生 fixture 通过 R0，再在真实游戏暂停边界通过 R0；写出被排除区段及理由。
不做：不做并行、不做增量、不处理设备状态。
规模：L。

### N6 跨界耦合清单与探针

目标：把 §3.4 的清单逐条定性。
交付：静态导入表 + 动态调用点追踪的候选清单；长挂起对短挂起、虚拟时钟两组探针。
验收：每条结论为"已固定 / 已证伪 / 待定"，附证据指针。
依赖：N5。
规模：M。

### N7 根一致性检查器

目标：落实降级后的 P2——根只要是合法引擎状态即可。
交付：遍历全部引用型 ID（`mTargetZombieID`、`mRelatedZombieID`、`mBodyReanimID` 等），检查目标存在、类型匹配、代次不撞车。
验收：能对 `.dat` 读档产生的根给出"一致 / 不一致 + 具体字段"。
规模：S。

### N8 同源分支自检流程与抽样策略

目标：把"同根同动作跑两遍逐帧比"做成常规自检。
交付：一条命令对一棵树抽检并产出报告；抽样比例与失败处理策略。
依赖：N3、N5。
规模：S。

### N9 虚拟音频设备与离线音轨

目标：同时解决音频反馈的确定性、原版音效语义的保留、视频音轨来源。
交付：hook DirectSound（以及音乐侧 API）的播放接口；tick 驱动的混音器回答 `IsPlaying` / `GetCurrentPosition`；同一模型离线生成音轨。
验收：silent 模式与虚拟设备模式在同一动作序列下逐帧一致，且能产出与游戏 tick 对齐的音轨。
规模：L，可延后。

### N10 并行分支 worker

目标：让训练管线可以同时跑多个分支。
交付：每分支独立用户档、日志、设备；worker 生命周期与失败隔离。
依赖：N5、N6、N7。
规模：L，可延后。
