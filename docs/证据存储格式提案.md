# 证据存储格式提案： `lvz-evidence/2`

当前 audit 用分文件 JSONL 保存每个边界的完整证据。本提案保留全部证据语义（逐字段、逐原始值、逐边界），只更换编码与组织方式，目标是把同一局实验的归档体积降低一个数量级，同时降低游戏线程的写入成本。它不是压缩方案：压缩只是可叠加的传输层。

## 现状实测（5000 tick 公开源实验 `public-fp-smoke-001-s42-c0`）

| 文件 | 体积 | 记录 | 平均/行 |
|---|---:|---:|---:|
| particle-shake-seeds.jsonl（原始粒子证据） | 490.6 MB | 695,940 | 740 B |
| events.jsonl（同一批调用的语义副本 + 边界事件） | 379.0 MB | 696,835 | 558 B（粒子行） |
| state-deltas.jsonl（每边界状态差分） | 344.5 MB | 10,000 | 36.1 KB |
| checksums.jsonl（逐记录摘要） | 17.7 MB | 10,000 | 1.8 KB |
| 其余（reanimation/FP/engine-call/sound-counter） | 24.2 MB | — | — |
| **合计** | **1.26 GiB** | | |

两个主要浪费来源：

1. **同一事件写两份。** 一次粒子播种同时写原始旁证（含地址，740 B）和语义副本（558 B），共 1,298 B/次，占全档 70%。两者的身份、种子、池计数完全重复，只有地址是原始侧独有。
2. **文本编码的定长开销。** 原始粒子记录有 31 个叶字段，键名与 `payload/` 前缀每行重复，约 330 B 只用于键；地址/种子写成 9–10 位十进制；状态差分的路径 `"/board/00005560"` + 操作名写 52 B，而语义只需“路径 id + 4 字节值”。10,000 个边界平均 391 个补丁操作、最多 5,602 个。

## 目标格式

单流、按边界分块、字典编码、二进制帧、哈希链。

```
audit/evidence.bin                 （可选外层容器 evidence.bin.zst）
  header      magic "LVZE2\0" | schema | target | dictionary_offset
  dictionary  字段名/路径/枚举字符串 → varint id（整档只写一次，之后只读）
  block[0..n] 每个受控边界一块：
                 u32 length
                 frames[]
                 u32 block_sha256[8]   该块字节摘要
                 u32 chain_sha256[8]   = H(前一块 chain ‖ 本块摘要)
  footer      边界数、末次 chain、清单摘要、关闭 health
```

帧类型（首字节为类型 id，其后字段 id/值用 varint）：

| 类型 | 内容 |
|---|---|
| `0x01 boundary` | pre/post、version 增量、engine_call id 增量 |
| `0x02 state_delta` | 补丁操作序列：路径 id、类型标签、值 |
| `0x03 particle_seed` | **原始与语义合并为一条**：地址按调用点基线做增量，种子/因子/时长/池计数为定长整数 |
| `0x04 spawn` | 僵尸初始化、首次边界观察 |
| `0x05 action/request` | 请求、动作结果、策略 |
| `0x06 raw` | FP/音效计数/引擎调用原始旁证（同边界同 id） |
| `0x07 close` | 各 hook 关闭 health、fault 锁存 |

编码规则：

- 只写整数与 32 位原始位模式，**不写浮点值**（沿用现行规则）。
- varint 用 LEB128 规范形式（禁止前导零），有符号用 zigzag；非规范编码即拒绝。
- 地址存相对于所在对象基址的增量，池计数与上一块做差分。
- 字符串只在字典里出现一次；一次性字符串才用长度前缀。
- 编码确定性：无时间戳、字典按 id 排序、帧顺序固定 ⇒ 同一轨迹两次录制产生相同字节。

## 体积与开销估计

编码估算直接用现有归档的原始字节做对拍：粒子证据取前 200,000 行逐字段按 varint/增量重算；状态差分按第 1,500 行后每 7 行抽 1 行（2,714 行、726,000 个补丁操作）重算，路径按字典 id 计。这是编码模拟，不是已实现格式的实测。

| 项目 | 现在 | 提案（模拟编码） | 倍数 |
|---|---:|---:|---:|
| 粒子播种证据 | 1,298 B/次（原始 740 + 语义 558） | ≈ 66 B/次（合并为一条） | **20×** |
| 状态差分 | 36.1 KB/边界（全档均值） | ≈ 2.4 KB/边界 | **≈ 15×** |
| 逐记录摘要 | 17.7 MB 独立文件 | 每块 64 B 哈希链，≈ 0.6 MB | **29×** |
| 其余 | 24 MB | ≈ 8 MB | 3× |
| **audit 合计** | **1.26 GiB** | **≈ 80 MB** | **≈ 16×** |

同一模拟中，粒子原始行的字段构成是 31 个叶字段、740 B 文本对 64 B 二进制；状态差分采样到 16,947 个不同路径，说明路径字典平均 id 约 2–3 字节。在此基础上叠加 zstd-3 容器后估计 30–40 MB（≈ 35×）。按同一比例外推完整两旗（约 55,800 tick）：源审计从约 14 GiB 降到约 0.9 GB（压缩后 ~0.35 GB），9 次冷重放同理，F 盘现有 52 GiB 余量足以容纳 strict 全流程。

写入成本同样下降：原生微基准显示 JSON diff/序列化占单边界 12.2–19.2 ms；二进制编码不再构造补丁对象与文本，估计降到 2–5 ms/边界，即每 tick 节省 20–30 ms，实测 114 ms/tick 的重放路径有望降到 85–95 ms/tick。这是估计值，实施后必须用同种子实测替换。

## 不变项（证据合同）

- 每个边界的**规范化 state 摘要继续按现行算法计算并保存**，跨运行身份与 `first_difference` 语义不变。
- 关闭顺序、hook health、fault 锁存、owner/preconditions 判定、`equal` 比较方式全部不变；只是读取器换了底层的字节来源。
- 每边界一块、块内完整 flush，**保留实时 tail 读取能力**（live 阶段仍是明文追加，封存时才落容器）。
- 旧 JSONL 档继续按旧合同读取，不升级、不重写；新模式由 manifest 明确声明。
- 提供 `tools/decode-evidence.py`，把 `evidence.bin` 还原成与现行 JSONL **逐字节等价**的文本，用于人工复核与外部审查；严格读取器直接读二进制。

## 打包去重：trajectory 不再复制第二份

独立于编码格式的第二个浪费：`build_trajectory` 用 `shutil.copyfile` 把 audit 的每个证据文件复制到 `trajectory/audit/`，归档体积直接翻倍（5000 tick：源 audit 1.23 GiB，trajectory 再 +1.23 GiB；即使经过容器压缩，也仍是 +50%）。

- **方案**：同一卷内用 `os.link()` 建**硬链接**而不是复制。字节数、SHA-256、`st_dev/st_ino` 完全相同，`records.local_files` 只拒绝符号链接、junction 和其他 reparse point，硬链接在其之上是合法常规文件。
- **身份声明**：manifest 额外记录 `packaging: "hardlink"|"copy"`、`link_group`（或每文件的 `st_dev/st_ino`），证明两处是同一份字节，而不是“另一份碰巧哈希相同”。跨卷（源在 F:、归档目标在 I:）或文件系统拒绝硬链接时回退为复制，并在清单里写明回退原因。
- **不采用符号链接/junction**：现行校验明确拒绝，且它们指向的目标被删除会直接损坏归档；硬链接在任一目录被删除后仍然完整。
- **与格式无关**：对当前 JSONL、gzip 容器和本提案的二进制单流同样适用。新格式下 `trajectory/` 只需链接一个 `evidence.bin` 加一个 receipt。
- **注意**：硬链接共享 inode，任何一处原地改写会同时影响另一处——这与现行“封存后只读 + 逐字节哈希 + inode/尺寸/时间戳签名”的约束一致，`EventStream` 的签名检查能发现替换。
- **收益**：归档总字节直接减半。5000 tick 由 148 MB 降到 74 MB（容器层）或 160 MB 降到 80 MB（二进制层），两旗 strict 全流程同理减半。

## 负例与验证

- 截断块、长度与实际不符、非规范 varint、未知路径 id、字典启动后被改写、chain 不匹配、缺 footer、二进制与 JSONL 混放 ⇒ 全部拒绝。
- 同一轨迹两次录制字节相同；`first_difference`、B0 比较、seek、takeover、terminal 补丁等现有 379 项测试全部沿用，另加原生编解码对拍测试。
- 实机验证：先用新格式跑 3 tick 预检，再用 5000 tick 与已通过的 JSONL 结果逐边界比对，确认解码后证据完全一致。

## 分阶段实施

1. **阶段一（低风险，约 2.5–3×）**：仍在 JSONL 内消除浪费——原始与语义粒子证据合并为一文件；用边界哈希链替代 `checksums.jsonl`；kind/phase 等枚举字典化；地址与原始字段映射改为紧凑字段；trajectory 改硬链接（这一项与本阶段其余改动独立，可先落地，直接省一半归档字节）。可立即实施，读取器改动小。
2. **阶段二（本提案主体，约 16×）**：单流二进制、按边界分块、字典与哈希链；双读取器 + decoder；新旧格式并存；打包继续沿用硬链接。
3. **阶段三（验收）**：同种子对比 tick 成本与归档体积，重跑 3 tick 与 5000 tick 官方入口，逐边界证明解码证据与旧格式一致后，才把新格式用于 strict 两旗与十次冷启动。

## 备选方案与取舍

- **列式存储（Parquet/Arrow 风格）**：压缩率与离线分析更好，但实时 tail 读者与“单边界失败隔离”都要求顺序帧，因此不作为主格式，只作为可选的导出格式。
- **只做压缩（gzip/zstd 包住现有 JSONL）**：实测 17×，改动最小，但不解决文本冗余与每 tick 序列化成本，且仍要写两份粒子证据。适合作为阶段零的过渡，与阶段一/二叠加仍有效。
- **改随机数提供者**：不采用。目标是重放原版引擎，替换随机源会改变原版行为，且 048 的分叉根因是 x87 浮点精度而非随机数。
