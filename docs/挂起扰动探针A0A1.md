## 1. 判据（A0/A1 共用）

判定来源是[跨界耦合清单](跨界耦合清单.md) §4.6 的四条，逐条落到可复核字段：

| # | 判据 | 由谁证明 | 检查名 |
|---|---|---|---|
| 1 | 挂起前后 `audit_snapshot` 的 `version` 与规范化 `state` 逐字段相等；声明固定 FP 模式时激活回执不变 | live 探针（`compare_snapshots`） | `version_unchanged`、`state_unchanged`、`observation_unchanged`（`observe` 也不变）、`fixed_fp_activation_unchanged` |
| 2 | 挂起区间内没有新增受控调用/边界，epoch 不变 | live 探针读 `engine_call` 计数器；离线再扫 `audit/checksums.jsonl` | `engine_call_counters_unchanged`；`boundary_sequence_strictly_increasing`、`engine_call_ids_contiguous`、`pause_<i>_paused_boundary_recorded_once` |
| 3 | 挂起后继续同一动作序列，与"同一源、短挂起"的对照逐帧相等 | 冷重放的 `replay-report.json` | `replay_equal`、`replay_requests_recorded`、`replay_pauses_executed`（轨迹含 `pause` 请求时才成立；见 §6.3） |
| 4 | 暂停覆盖率为 `pass`，且 `pause_invariance` 门槛为 `pass` | 会话目录的 `pause-probes-during-play.json` / `pause-probe.json` | `pause_coverage_pass`、`pause_at_<tick>.*` |

三态判定（`suspend_probes.judge` / `assess`）：

| 结论 | 何时 | 不允许写成 |
|---|---|---|
| `pass` | 全部检查为真 | —— |
| `fail` | 任一被比较的字段变了、墙钟没走满、边界序列出现缺口/重复、冷重放 `equal=false` | "部分通过"、"下次就好了" |
| `unverified` | 检查本身成立，但**证据缺失**：没扫到 audit、没有 replay 报告、扰动没施加成功（例如 `SetForegroundWindow` 被前台锁定拒绝） | `pass`。缺证据一律不算通过 |

## 2. 方法与实现落点

| 文件 | 内容 |
|---|---|
| [src/llm_vs_zombies/suspend_probes.py](../src/llm_vs_zombies/suspend_probes.py) | `probe()`（live A0/A1）、`apply_perturbations()`（`wall`/`focus`/`cursor`，含 `simulated` 模式）、`judge()`（判据重算）、`boundary_records()`/`boundary_checks()`（离线扫原生 audit）、`assess()`（A1 目录评估）与 CLI (`python -m llm_vs_zombies.suspend_probes probe\|assess`) |
| [src/llm_vs_zombies/evaluation.py](../src/llm_vs_zombies/evaluation.py) | `Plan.pause_perturbations`（缺省空）+ `--pause-perturbations`；`_pause_probe(..., perturbations=...)`；`PauseSchedule` 把声明透传到每个暂停点 |
| [tests/test_suspend_probes.py](../tests/test_suspend_probes.py) | 18 项离线夹具：判据重算、扰动顺序与还原、模拟模式、状态漂移判 `fail`、扰动失败判 `unverified`、A1 目录评估（含 gzip 归档与缺失 audit） |

三条不改变既有行为的设计约束：

1. **缺省不注入**：`pause_perturbations` 为空时 `_pause_probe` 不发送任何扰动，返回的探测记录与改动前**同键同值**（`tests/test_suspend_probes.py::EvaluationProbeTests::test_undeclared_run_keeps_the_legacy_probe_record` 锁定键集）。
2. **扰动失败不静默**：单个扰动施加失败只把该条记为 `applied=false` 并带上原始错误，整体判 `unverified`，不会被当成"无影响"。
3. **状态变化立即失败**：暂停期间 `state`/`version`/`observe` 任一处变化时 `_pause_probe` 仍按旧行为抛错，`pause-probes-during-play.json` 记 `probe_failed`，覆盖率转 `fail`（沿用现有门槛，不放宽）。

扰动种类：

| 种类 | 做什么 | 记录 |
|---|---|---|
| `wall` | 真正把墙钟推进 `seconds`（每个探针都执行） | `requested_seconds`、实测 `wall_seconds` |
| `focus` | 把前台窗口切到桌面/外壳窗口，再切回原前台 | `before`/`target`/`after`（HWND、PID、标题）、`restored` |
| `cursor` | 光标移到屏幕右下角，再放回原位 | `before`/`target`/`after` 坐标、`restored` |
| `simulated`（`--simulate`） | 只记录意图，不动桌面；墙钟照旧推进 | 每条 `simulated=true` |

## 5. 真机步骤清单（给主 agent）

前置：一次只跑一个游戏进程；每个世界用自己的检出与 run 目录；先 `tools/prepare-checkout.ps1`，`game/` 私有文件按 `dependencies.lock.json` 校验。**A0 与 A1 都不要与其它真机任务并行**（会污染窗口采样与掉帧归因）。

### 5.0 顺带核对launcher分支身份（issue #50 子项 1 的真机部分）

A0/A1 的 run 本身就是分支身份的真机证据，取数时一并记录：`launcher.json.branch_id`、`launcher.json.branch_source`、`sandbox/native-receipt.json.branch_id`、`hello.branch.branch_id`、`manifest.json.branch.branch_id`、`evaluation` 轨迹初始 marker 与重放报告的 `branch_scope.runtime_branch_id` —— 六处必须等于该 run 的目录名（显式 `--branch-id` 时等于该值）。任一处不等，或 `hello.branch.mode` 不是 `branch`，该 run 的启动就应已失败并停止自有进程；若没有失败，按缺陷记录，不要把它当通过。历史档（`branch` 缺省）应当仍然可读、可校验、可重放。

### 5.1 A0（不动 plan，任意时长）

1. 建新 run 并隐藏启动，停在可暂停的边界（沿用现有做法：`launcher.py start --defer-preparation` 或 REPL 会话）。
2. 施加扰动并记录：

   ```powershell
   $env:PYTHONPATH = 'src'
   python -m llm_vs_zombies.suspend_probes probe --pid <PID> --seconds 300 `
       --perturb wall,focus,cursor --branch-id <run 名> `
       --trace <run>/decisions/a0-trace.jsonl --output <run>/suspend-probe-a0.json
   ```

   `--branch-id` 可省；给出时连接会绑定到该 runtime 分支作用域，名字不符直接失败（identity 一致的另一道保险）。若桌面策略不允许抢前台，可加 `--simulate`，此时焦点/光标项只记意图，结论只能覆盖 `wall`。
3. 要记录的数：run 目录；PID 与创建时间；`recorder.dll`/`lvz-launcher.exe`/`lvz-bootstrap.dll` 的 SHA-256；`requested_seconds` 与实测 `wall_seconds`；`version`；`state_sha256`；三条扰动的 `before/target/after/restored`；`checks.*`；`verdict`。
4. 看什么算通过：`verdict=pass`、`checks.*` 全为 `true`、`wall_seconds ≥ requested_seconds`、`focus`/`cursor` 的 `applied=true`。若 `SetForegroundWindow` 被系统拒绝（前台锁定），该条会写成 `applied=false` + `winerror`，整体判 `unverified`——**记录它，不要当作通过**。
5. 结论边界：本探针只覆盖"隐藏窗口 + 控制器暂停"；锁屏、断开桌面会话、纯无显示设备、被冻结的进程都不在其内。

### 5.2 A1（走公开 runner，源 + 冷重放）

1. 写计划（暂停点用现有 0.05–10 s 上界）：

   ```powershell
   python -m llm_vs_zombies.evaluation plan work/a1-pause-plan.json --tier smoke --seeds 42 `
       --tick-budget 3000 --cold-starts 1 --audio-mode sound_effects_allocation_none_v1 `
       --pause-points '[[500,0.05],[1000,1.0],[2500,10.0]]' `
       --pause-perturbations '["wall","focus","cursor"]' `
       --b0-normalize '{"field":"/sound_effects/app_update_count","target":2048,"reason":"B(0) 前 App 循环圈数"}' `
       --b0-normalize '{"field":"/app/mj_clock","target":2048,"reason":"舞者相位绝对计数"}'
   python -m llm_vs_zombies.evaluation run work/a1-pause-plan.json --output experiments/runs/a1-pause-001
   ```

   修正 ①（2026-09-24 真机）：清单原先只写到 `--pause-perturbations` 一条，缺上面两条 `--b0-normalize`；按旧文字跑会在初始化即以 `RuntimeError: runtime declares the unified B(0) normalization; declare the fixed common target of every declared field explicitly…` 失败。失败档 `a1-pause-001` 原样保留（其 `plan.json` 的 `b0_normalization` 为空、`seed-42-case.json` 记该错误），未重跑顶替；同日的通过档 `a1-pause-002` 的 `plan.json` 里 `b0_normalization` 正是本块两条，次序 = 命令行次序。

2. 离线复核（源会话 + 冷重放报告）：

   ```powershell
   python -m llm_vs_zombies.suspend_probes assess `
       --run experiments/runs/a1-pause-001-s42-c0 `
       --replay-report experiments/runs/a1-pause-001/seed-42-replay-1/replay-report.json `
       --output experiments/runs/a1-pause-001/suspend-probe-a1.json
   ```

## 6. 边界与未做

1. **A2（≥300 s）未做**：需要放宽 `Plan.validate` 的 pause 上界（0.05–10 s）。放宽时只动这一处，不动冷重放、封存与窗口门槛。
2. **A3（冻结挂起）未做**：需要 `tools/process_snapshot.py --hold-seconds N`（复用 `suspend_threads`/`quiesce`/`resume_threads`，与 `--r0` 互斥）。
3. **焦点扰动的可达性**：`SetForegroundWindow` 常被 Windows 前台锁定拒绝；探针把它记为 `applied=false`，结论落 `unverified`。因此"焦点扰动无影响"这句话只有在真机取到 `applied=true` 时才成立。
4. **光标扰动的范围**：只覆盖"移动位置"；不覆盖锁屏、无输入桌面、鼠标按键/滚轮与触屏输入。
5. **不改 C17/C18/C19 的清单状态**：本文不把任何条目从"待定"升级；升级需要 §5 的真实证据。
6. **不触碰 B 组（虚拟时钟）**：`docs/跨界耦合清单.md` §5 的状态不变。

### 6.3 冷腿没有"重新执行暂停"这一层（实测口径，非失败）

今天 plan 驱动的暂停是**客户端墙钟等待**：`PauseSchedule` 只发 `status`/`audit_snapshot`/`observe`，不把 `pause` 写进源轨迹（`fork-a1-s42-c0` 的 `decisions/evaluation.jsonl` 里 `pause` 请求数为 0，其 `replay-report.json` 的 `pause_controls` 为 `{recorded:0, executed:0, verified_noop:0}`）。因此 A1 的冷腿证据是"**逐帧相等**"（`replay.equal=true` + 原生边界扫描），**不是**"冷重放又执行了一次暂停"；`assess` 会在 `replay.cold_leg_note` 里点名这条边界。

要让冷重放真的执行暂停，需要把 `pause` 请求写进源轨迹（参数必须为空、只能接在一次 `executed_ticks>0` 的推进之后，并在其后补一次 `audit_snapshot` 作为 `state_after`，见 [engine_replay.py](../src/llm_vs_zombies/engine_replay.py) 的 pause 校验）。这属新的实现工作，本 issue 未做，也不因此把 A1 判成失败——`跨界耦合清单` §4.3 关于"源录制期间真的插入 pause 请求"的描述与当前实现不符，本文按实测口径记录，不改写该文。
