# 虚拟音频设备与离线音轨

日期：2026-09-22。对应 issue [#37](https://github.com/guajun/llm-vs-zombies/issues/37)（[N9] 虚拟音频设备与离线音轨），Epic [#39](https://github.com/guajun/llm-vs-zombies/issues/39)。模式名 `virtual_audio_tick_v1`。模型与离线渲染：`src/llm_vs_zombies/virtual_audio.py`；工具：`tools/offline_soundtrack.py`；测试：`tests/test_virtual_audio.py`。

范围声明：本文给出**语义规格**、**宿主侧模型**与**离线工具**，并写明原生 hook 的落地点和所需接口。本提交**没有**在游戏进程内实现该模式，**没有**启动游戏，也**没有**真实录像验收（§8 列出前置条件）。`virtual_audio_tick_v1` 与 `sound_effects_allocation_none_v1` 同级：它改变实验语义，旧档不能追认为该模式，历史失败结论不受影响。

## 0. 摘要

- policy、视频、随机消费三条需求用一个模型解决：`IsPlaying` 与 `GetCurrentPosition` 都由**游戏 tick 与音效时长**回答，不读声卡、不读墙钟。
- 声明：仿真侧**保持 allocation-none 的准入剖面**（`GetSoundInstance` 仍返回 null）。这是"与 silent 模式逐帧一致"唯一可行的构造；把设备答案交回 Foley 准入路径的设计（§4 接线 B）在模型里作为反例保留。
- 代价：本模式不复现原版"10 更新内拒绝重放 / `ONE_AT_A_TIME` 复用"的**可听**行为；这两条门在离线渲染侧用 tick 驱动的 `IsPlaying` 重建，并且只影响音轨，不影响仿真。
- 交付物：混音器语义（§3）、两条接线与声明差异（§4）、原生落地接口（§5）、离线音轨工具与覆盖核对（§6）、模型级逐帧一致证明（§7）、未做与前置条件（§8）。

## 1. 三条需求与它们的冲突

| 需求 | 约束来源 | 若被违反 |
|---|---|---|
| policy 不读音频 | 观察面分层；音频状态不进 S | 策略会依赖设备/机器 |
| 视频要能出声 | `docs/video.md`（当前 mp4 用 `-an`，只有画面） | 录像无法用于人看/宣传 |
| 音频查询不得改变随机消费 | 036 实测：`IsPlaying` 返回值进控制流 | 同一动作序列逐帧不一致 |

冲突是**实测**的，不是推测。036 对照（记录见 `work/issue12-foley-cause-confirmed.md`、"036"条与 `docs/headless-validation.md`）给出的完整链是：

1. 目标 slot `refcount=1`、`start_count=2636`、App counter `=2640`，`elapsed=4 < 10`；
2. 原版 `IsPlaying`（`0x514FA5` 的真实返回）fast 返回 `AL=1`、delayed 返回 `AL=0`；
3. `AL=0` 走 `SoundSystemReleaseFinishedInstances` 的释放分支：instance/refcount 清零；
4. 于是"10 更新内已播过"的门（`SoundSystemHasFoleyPlayedTooRecently`，`docs/机制读取点表.md` L49）在两侧取值相反，一侧直接返回、**不执行变体选择**；
5. 另一侧执行 `0x515188` 的真实变体抽取：MT cursor `199→200`，整局由此平移。

因此：任何"把设备答案交回仿真"的虚拟设备，都与 `sound_effects_allocation_none_v1` 逐帧一致互斥。issue #37 的验收要求 silent 与虚拟设备逐帧一致，所以本模式必须在"仿真侧剖面"和"可听行为"之间做一次明确取舍，并把取舍写进声明（§4、§9）。

## 2. tick 与时间基

- 受控运行的 tick 就是动作/观察边界的 tick（`version.tick`，`docs/runtime-protocol.md`）；一秒 100 tick，即 1 tick = 10 ms（`mFrameTime = 10`，`docs/机制读取点表.md` L57）。
- 采样率取 44100 Hz。`44100 / 100 = 441`，**每 tick 恰好 441 个采样**，没有余数，音轨与 tick 网格因此能做整数对齐（`tools/offline_soundtrack.py` 与 `video.py` 的 `ticks_per_second=100` 同网格）。
- 模型不读墙钟：音频事件的时间戳一律是 tick，`tests/test_virtual_audio.py` 用"读 `time.monotonic`/`time.time` 就失败"的 mock 固定这一点。
- 原版"10 cs"门与 tick 同量纲（10 tick），这一点让"离线重建准入"不需要墙钟。

## 3. tick 驱动的混音器语义

一个 voice 对应一个虚拟 `TodDSoundInstance`：一块源缓冲 + 一个播放游标。设备接口就是 DirectSound 侧与 `SoundInstance` 侧真正会被调用的那些写操作与查询（`work/replay-research/SexyAppFramework_DSoundInstance.cpp`、`Sexy.TodLib_TodFoley.cpp` 的参考源）。

| 调用 | 原版动作 | 模型动作 |
|---|---|---|
| `GetSoundInstance` | 管理器找空通道、新建实例 | 由接线决定（§4） |
| `Play(loop, autoRelease)` | `Stop()` 后 `Play`，游标回 0 | 关闭当前段，开新段，`offset=0` |
| `Stop()` | `Stop()` + `SetCurrentPosition(0)` | 收段，`stopped=True`，游标读 0；实例仍可用 |
| `Release()` | `Stop()` + 退休 | 收段并 `released=True`（终态） |
| `GetStatus & DSBSTATUS_PLAYING` | 声卡状态位 | `is_playing(tick)`（下式） |
| `GetCurrentPosition` | 声卡缓冲游标 | `current_position(tick)`（下式），字节数 = 样本 × 4 |
| `SetCurrentPosition(x)` | 跳游标 | 收段，用 `offset=x` 开新段（游标连续） |
| `SetFrequency(f)` | 整数 Hz | 按 `rate = f / 44100` 开新段（游标连续） |
| `SetVolume` / `SetPan` | 属性 | 收段 + 新段带新参数（声明的线性 pan 律，非原版百分之一分贝律） |
| `GamePause(true/false)` | `GetSoundPosition()` → `Stop()`；恢复 = `Play()` + `SetSoundPosition(offset)` | `pause()` / `resume()`，见下 |

时间与查询（`t` = 查询 tick，`spk` = 441，段从 `origin` 起、游标初值 `offset`）：

```
cursor(t)      = offset + floor((t - origin) * spk * rate_num / rate_den)
end_tick       = origin + ceil((duration_samples - offset) * rate_den / (rate_num * spk))
is_playing(t)  = t < end_tick                       （非循环，且 t >= origin）
               = True                               （循环，直到 stop/pause）
position(t)    = min(cursor(t), duration_samples)   ；播完返回 duration_samples
               = cursor(t) mod duration_samples     （循环）
               = 0                                  （已 Stop 或暂停：缓冲被 `SetCurrentPosition(0)` 复位）
```

- 暂停：`pause_offset = position(t_pause)`，然后收段、`stopped=True`、`paused=True`；恢复时以 `pause_offset` 开新段（`Play()` + `SetSoundPosition` 的等价）。可听上是"暂停期间静音，恢复后从原游标继续"。
- 音高：`AdjustPitch(steps)` 用原版常数 `1.0594630943592952645618252949463`（= 2^(1/12)），`freq = int(44100 * 常数^steps)` 限幅 `[100, 100000]`，再取有理数 `rate = freq/44100`。整数 Hz 舍入是**声明**的建模步骤，与原版 `SetFrequency((DWORD)freq)` 同形；因此本模型的时长会随音高改变（抽样率上等价于原版缓冲被更快消费）。
- `source_kind`：`tone`（声明振幅的确定性占位信号，测试与未准备资源用）或 `file`（必须是 44100 Hz、16-bit PCM WAV；其余格式要求先转码，工具不内置解码器）。

**明确不做**（不声称、不建模）：主缓冲/硬件混音、原版百分之一分贝音量与 pan 律、原版混响/EQ、`WAVEOUT`/`mixerSetControlDetails` 的实际输出、原版解压后的位精确采样。本模型声明的是**tick 对齐与覆盖**，不是字节级音质还原。

## 4. 两条接线与声明差异

| | 接线 A：观测式（本 issue 实现） | 接线 B：反馈式（模型反例，未实现） |
|---|---|---|
| `GetSoundInstance` | 保持 null（= allocation-none 剖面） | 返回活体虚拟实例 |
| `IsPlaying` / `GetCurrentPosition` 交给谁 | 只给离线渲染、音乐侧与证据面 | 交给 Foley 准入路径（`0x514FA5`） |
| 与 silent 逐帧一致 | **是**（§7 模型级证明） | **否**：036 机制，抽数更少（§7 反例测试） |
| 可听行为 | 离线重建（含 10 更新/`ONE_AT_A_TIME`/8 槽，§6） | 原版式门控 |
| 需要的新验收 | 模式协商 + 证据链 + 音轨覆盖（本提交给出模型与工具） | 还需独立的"设备在环"重放验收 |
| 风险 | 音轨不是"当时实际听到的"，是"被准入的播放意图"重放 | 逐帧一致直接失效 |

接线 A 的语义改动范围（本模式的声明）：

1. **仿真侧与 `sound_effects_allocation_none_v1` 相同**：每个被准入的 Foley 调用仍消耗一次变体抽取、`GetSoundInstance` 仍返回 null；slot 表、refcount、`mStartTime`、`mPauseOffset` 与 silent 模式逐帧一致。
2. **新增只读观测**：在 `PlayFoleyPitch` 的变体抽取点记录 (type, variation, resource, pitch, tick)。观测点不改返回值、不额外调用原版函数；它只影响墙钟（`docs/foley-diagnostic-trace.md` 已声明的同类扰动），不影响 tick 语义。
3. **新增设备侧虚拟化**：DirectSound/BASS 侧的播放、停止、位置查询不再落到真设备（§5）。对仿真无输入，对音轨/录像有输出。
4. **音乐侧位置查询变为 tick 驱动**：`Music::GetMusicOrder`（`Lawn_System_Music.cpp:431-434`）一类查询由模型回答。机制读取点表 L52 的结论是"不进 S，但设备状态须固定"，本模式把这个"固定"从"机器相关"改成"tick 相关"。

## 5. 原生 hook 落地点与所需接口（未实现）

### 5.1 仿真侧：保持 silent 剖面 + 只读观测

`GetSoundInstance` 前缀补丁沿用 `launcher/silent_audio.cpp` 的做法：核对引擎 SHA-256 `f9669af338964787a3785a7895791297d599295b8bb669b0db49443f736a1322`、PE `ImageBase 0x400000` / `SizeOfImage 0x394000`、入口 `0x5c7650` 的 6 字节 `55 8b ec 83 e4 c0`、虚表槽 `0x675ff4` 指向该地址，然后写 6 字节跳转，`EAX=0`、保留寄存器/标志/FP 状态、`ret 4`；预恢复前可回滚，封存后不可。

只读观测点（地址与 `docs/foley-diagnostic-trace.md` 的十二处同源，但本模式只需要其中一部分；全部先做签名核对、失败即 fail closed）：

| 观测点 | 地址（该引擎） | 产出 | 备注 |
|---|---|---|---|
| `PlayFoleyPitch` 入口 | `0x515020` | type、`pitch_bits`、参数表指针、MT cursor | 事件流的时间戳来自 tick 上下文 |
| 变体 `Rand` 前/后 | `0x515188` / `0x51518D` | 候选表、真实抽取结果 | 变体是音轨的必需字段 |
| `GetSoundInstance` 返回 | `0x5151B5` | 分配结果（本模式恒为 null） | 用于声明"分配失败仍记录播放意图" |
| `StopFoley` | `0x515290`※ | 停止请求 | 现有 foley trace **没有**这个 site，需新增 |
| `GamePause` | `0x5152D0`※ | 进入/离开暂停 | 同上 |
| `CancelPausedFoley` | `0x5153F0`※ | 丢弃暂停实例 | 同上 |

※ 这三个地址来自参考源 `Sexy.TodLib_TodFoley.cpp` 的函数注释，**尚未**由本项目独立反汇编核对；落地前必须像 §5.1 第一段那样先核对首字节与调用点，任何不符即 fail closed。

需要的接口（与既有模式协商形状一致）：

- 环境变量 `LVZ_AUDIO_MODE`，取值 `original`、`sound_effects_allocation_none_v1`、`virtual_audio_tick_v1`；未知值拒绝启动。
- bootstrap 导出（POD/限长）：`LvzAudioStatus`、`LvzAudioSeal` 之外增加 `LvzAudioEvents`（按 tick 排序的定长环形队列读取）与只读 `LvzAudioHealth`；不得在 hook 内分配、序列化或调用原版随机函数。
- manifest：`game.sound_effects` 增加该模式子树（`mode`、`installed`、`activation`、`entry_rva`、`original_bytes`、`engine_sha256`、`bootstrap_sha256`、`sound_allocation`、`music_virtualized:true`、`original_engine_bitwise_unmodified:false`、`live_verified:false`），`capabilities.virtual_audio_tick_v1` 必须与子树一致。
- 独立证据：`audio/virtual-events.jsonl`（`lvz.audio-event.v1`，§6）、`audio/mixer.json`（时间基、采样率、每 voice 的段与终点）；关闭事件 `virtual_audio_closed`，语义失败要**latch**（沿用 `docs/silent-audio.md` 的健康口径）。
- 记录/回放两侧都要显式携带该模式：回放器不得把旧档"升级"成该模式，也不得把该模式静默降级成 `original`。

### 5.3 与视频对齐

`video.py` 的网格是 `epoch` + `start_tick` + `tick_stride` + `ticks_per_second=100`，`timing_basis="game_tick"`。音轨 manifest 必须携带同一组量；`tools/offline_soundtrack.py --video-manifest` 会在写盘前核对 `timing_basis`、`ticks_per_second` 与 `start_tick` 偏移，偏移非 0 时拒绝直接 `--mux`。

## 6. 离线音轨

### 6.1 输入

`lvz.audio-event.v1`（JSONL，一行一个事件；`seq` 严格递增，`tick` 非递减）：

| 字段 | 含义 |
|---|---|
| `kind` | `play` / `stop` / `pause` / `resume` |
| `type_id` | Foley 类型（`stop`/`pause`/`resume` 作用于该类型的第一个活体 voice） |
| `resource`、`variation` | 资源 id 与真实抽到的变体（`play` 必需） |
| `rate`、`pitch_steps` | 播放率（有理数）与产生它的音高步数 |
| `volume`、`pan`、`loop` | 声明电平/声道/循环 |
| `voice`（可选） | 直接指定目标 voice |

`lvz.audio-resources.v1`（声音表 + Foley 类型表）：`duration_samples`、`base_volume`、`pan`、`loop`、`source`，类型表的 `flags`（`loop`/`one_at_a_time`/`dont_repeat`/`mute_on_pause`/`uses_music_volume`）。类型表只服务**离线准入策略**；事件本身已经带上解析后的播放参数，二者不重复解释。

从真实记录派生：`virtual_audio.events_from_foley_trace` 逐 invocation 配对 `foley_enter` / `variation_return` / `foley_return_*`，产出 `play` 事件。**不要求分配成功**（allocation-none 下分配必然失败，但变体与参数已经确定）；`recent_return`（被拒调用）不产出事件。`StopFoley`/`GamePause` 目前没有 hook，需要 §5.1 新增 site。

### 6.2 渲染与覆盖

- 帧数 = `(end_tick - start_tick) × 441`；每个 voice 由若干段组成（暂停切断、恢复续接），`frames` 只统计真正写入的样本，`silent_frames` 是总帧数减去各段区间的并集。
- 输出 16-bit PCM、44100 Hz、立体声 WAV；manifest 记录每段的 `start_tick`/`end_tick`/`offset_samples`/`frames`/`rate`/`volume`/`pan`，以及 `union_frames`、`sum_voice_frames`、`clipped_values`、`pcm_sha256`。
- 循环 voice 必须有显式 `end_tick`：模型拒绝为循环音发明一个终点（工具报错要求传入）。
- `--admission original`（默认）在渲染侧重建原版门：同类型活体 voice 且 `is_playing(tick)` 为真、最近一次开播在 10 tick 内且不是 `loop` 类型 → 丢弃（`recent`）；`one_at_a_time` 类型仍有活体 voice → 丢弃（`reuse`）；同类型活体 voice 达 8 个 → 丢弃（`no_slot`）。`--admission all` 则逐个播放（用于对照与调试）。离线门用的是**模型的** `IsPlaying`，不读设备。
- `verify` 子命令重新核对：WAV 参数与 manifest、tick 网格 → 帧数、每段边界落在 tick 网格上、段帧数不超过跨度、voice 首末帧等于其各段、`union`/`silence`/`sum` 三账一致、`play` 事件 = voice + dropped、payload SHA-256 相符。

命令：

```powershell
$env:PYTHONPATH = 'src'
python tools/offline_soundtrack.py build --events events.jsonl --resources soundscape.json `
    --wav track.wav --end-tick 6000
python tools/offline_soundtrack.py verify --wav track.wav --manifest track.audio.json
python tools/offline_soundtrack.py build --events audit/foley-events.jsonl --from-foley-trace `
    --resources soundscape.json --wav hf.wav --end-tick 3000 --video-manifest clip.video.json `
    --mux clip.mp4 --output clip-with-audio.mp4
```

## 7. 测试与模型级证明

`tests/test_virtual_audio.py`（33 项）在**合成事件流**上验证：

| 组 | 覆盖 |
|---|---|
| 时间基 | 1 tick = 10 ms = 441 样本；采样率/每秒 tick 必须整除 |
| 混音器语义 | `is_playing`/`current_position` 只由 tick 与时长决定；音高改变终点；循环不回绕终点；`Stop` 归零、`Release` 退休；暂停读位置、恢复续接；`SetCurrentPosition`/`SetFrequency` 游标连续；查询与顺序无关；同一输入两次运行状态一致；非法输入拒绝；管理器 32 通道耗尽与释放后复用 |
| 音轨 | 帧数 = tick 网格；显式终点保留尾部静音；重叠 voice 报并集而非求和；暂停切断与恢复续接的段账；准入 `original`/`all` 差异；循环需要显式终点；渲染不读墙钟；`verify` 能拒绝被篡改的 manifest/截断的 WAV |
| **逐帧一致（模型级）** | `observe_only` 接线与 `sound_effects_allocation_none_v1` 的**每一帧**（80 tick、含同 tick 重放、12 tick 后重放、`ONE_AT_A_TIME`、loop 类型、暂停/恢复、`IsFoleyPlaying` 查询、`CancelPausedFoley`）逐字段相同；随机抽数、outcome 序列、`IsFoleyPlaying` 返回值、slot 剖面、`GetSoundInstance` 调用数全部相同；同时虚拟混音器确实产生了 voice，并且它回答过 `is_playing`/`pause_offset`（只用于离线准入） |
| 反例 | `device_feedback` 接线与 silent 在**首帧**即不同（slot 剖面），随机抽数更少；第 2 次调用在 silent 是 `no_instance`、在反馈接线是 `recent`；`IsFoleyPlaying` 在反馈接线为 `true`、silent 为 `false`（即商店台词计时那一类读取者会分叉）；App counter 冻结的暂停窗口会把差异放大 |
| 适配器 | 从 `lvz.foley-event.v1` 行派生事件只用真实抽到的变体、忽略被拒调用；事件流 JSONL 往返严格；soundscape 往返一致 |
| 工具 | `build` → manifest/覆盖 → `verify` 通过；篡改后 `verify` 返回 1；拒绝覆盖既有产物；`--video-manifest` 网格检查；`--from-foley-trace` 输入 |

这是**模型级**证明：它证明"声明的接线不会把设备答案送回仿真"，以及"tick 驱动的答案本身是确定的"；它**不**证明游戏内实现正确（§8）。

## 8. 未做 + 前置条件

1. **游戏内实现未做**：本提交只有主机侧模型、工具与文档。前置条件：§5.1 的窗口/接口落地、模式协商与 receipt 绑定、`audio/*` 证据进入档案哈希、关闭事件与健康口径接入现有 `sound_effects` 读取链。
2. **未启动游戏、未跑长局**：无录像、无冷重放、无逐帧对照。前置条件：新模式必须新录源（旧档不追认），并做 silent vs 虚拟设备同动作对照 + 冷启动初始化 + 预算/录像对照。
3. **真实资源时长表未生成**：`sounds/*.mo3|ogg` 需要先转成 44100 Hz、16-bit PCM WAV（工具只读 WAV，其它格式明确报错），`FoleyParams` 的 10 个资源指针 → 声音 ID 的映射需要按 `docs/机制读取点表.md` D3/§2 取证。当前测试全部使用声明过的 `tone` 占位信号。
4. **音乐侧未 hook**：BASS 的位置/状态查询只给出接口与落地点，未实现、未取证指令签名；`docs/机制读取点表.md` L52 仍是"exclude，但设备状态须固定"。前置条件：`bass.dll` 导入按名解析点的动态取证（`docs/跨界耦合清单.md` §2/§3.2）。
5. **声卡对照未做**：没有做"真实声卡 vs 虚拟设备"的音质/时序对照，也不声称字节级还原原版混音（§3 明确不做的部分）。
6. **FFmpeg mux 未进 CI**：`--mux` 只在显式给出时执行，缺 FFmpeg 时明确报错；本地 CI 不覆盖它。
