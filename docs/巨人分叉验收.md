# 巨人分叉验收：不同 Action 的分叉成立

日期：2026-09-23。状态：**本机实测通过**（范围见末节）。

## 判据

1. **每条分支自身可复现**：该分支的冷重放与自己的 source 逐边界内容摘要相同
2. **差异只出现在分叉点之后**：两分支的前缀逐边界相同，首个不同落在分叉动作那一帧
3. **分叉动作真正生效**：不是被引擎拒绝的无效动作

## 结果

| 判据 | 结果 |
|---|---|
| fork-a1 冷重放 == source | 4000/4000 边界，digests 全同 |
| fork-b1 冷重放 == source | 4000/4000 边界，digests 全同 |
| A vs B 首个不同的边界 | **index 802 = tick 401 = 分叉动作所在帧** |
| A vs B 相同前缀 | **802 个边界**（此前全同） |

同一个巨人（槽 11，ID `0xDF79000B`）在两分支的时间线：

| 事件 | A（诱饵 col 7） | B（诱饵 col 6） |
|---|---|---|
| 进砸击（phase 70） | tick 402 | tick 915 |
| 命中（`anim_time_reached_0.64`） | 534 | 1047 |
| 小喷菇被压扁 | **535** | **1048** |
| 后摇保持结束（`loop_count=1`, `anim_time=1.0`） | 608 | 1121 |
| **恢复行走 + 移速重采样** | **609 → `0x3e915324`（0.2838）** | **1122 → `0x3ebcd78a`（0.3688）** |
| 重采样时的全局 MT 游标 | 140 | 380 |

B 的诱饵更靠左，巨人要多走一列才进入索敌范围，于是砸得更晚、停在不同位置，重采样时的 MT 游标不同，抽到的速度也就不同——与 D6 钉下的链路（`anim_smash` 的 `mLoopCount` → `StartWalkAnim` → `PickRandomSpeed` → `RandRangeFloat(0.23,0.37)`，字段 `+0x34`）一致。

## 为什么上一版分叉没生效

上一版把分叉设计成"**同一 tick 再种一株小喷菇**"（`{"op":"plant","type":8,"row":6,"col":6}`，`advance_ticks=0`），被引擎拒绝：

```
error=card_not_usable   executed_engine_calls=0
observation.seeds: {"type":8,"slot":9,"usable":false,"initial_cd":750}
```

同一张卡在同一 tick 用了两次，冷却未就绪（前一条 `{"op":"plant","type":8,"row":6,"col":7}` 已 `ok:true`）。

现改为**诱饵换列**：A 种 col 7、B 种 col 6，每个分支只用该卡一次，动作成功（`ok:true`，`plant_id 3697344577`），且两文件仍然逐 AST 只差这一个常量。

## 不声称什么

- **不等于严格档门槛**：本轮是 smoke 档，主动排除 `full_cycle` / `ten_cold_starts`
- **这不是"同 Action 的平行世界"验收**：本轮的 A/B 是**不同 Action**（诱饵列不同）的分叉，证明的是"分支差异可控且各自可复现"；"同 Action 两世界一致"另见 `docs/平行世界S(A)=S(B)验收.md`
- 两条分支的"不同结局"是设计使然，不作为"哪个更好"的评价
