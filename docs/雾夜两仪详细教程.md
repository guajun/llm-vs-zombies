# 雾夜两仪无炮：运阵、TAS 练习与 LLM 评测教程

适用对象：已经了解《植物大战僵尸》一代基本操作，希望学习两仪，或希望让 LLM 通过 AvZ 暂停、逐帧操作的读者。核查日期：2026-09-18。

**两仪的难点是用极少的常驻植物，协调寒冰、灰烬、垫材与阳光，让持续输出有足够时间完成击杀。** 暂停和逐帧能降低操作速度要求，但不能免除对威胁、卡片周转和核坑的判断。

本文以 AvZ 官方教程附带的六花两仪存档及代码为可追溯参照。源码固定在 `c42676c269b5b482a1eb9203a5b979e9d8a2a5c7`。文中会明确区分三类内容：**源码／存档核查结果、已有作者资料、本文给出的练习与评测建议**。没有在实际 PvZ 进程中试跑本文流程，也不声称本文能保证任意出怪永久稳定。

## 1. 先决定练的是哪一种“两仪”

本文讨论 PC 原版机制的雾夜无尽，即六行、第三与第四行为水路的场景。不同游戏版本、五花／六花、守梯、加猫等变体，不应混为同一个测试场景。原作者的《九章阵华录》明确限定其阵型讨论基于 PC 1.0 版；其他版本要先核验机制。[原作者说明](https://tieba.baidu.com/p/5272254427)

学习时建议从**已成型阵型的运阵**开始。它与从空场建阵是两个任务：

| 任务 | 起点 | 主要要解决的问题 |
|---|---|---|
| 已成型运阵 | 常驻植物已齐、给定阳光与冷却状态 | 不破阵、卡片不断档、经济可持续 |
| 从零建阵 | 初始空场或早期关卡 | 过渡防守、生产阳光、升级植物、逐步撤掉过渡植物 |
| TAS 搜索 | 同一个初始状态，可以分支尝试 | 找到能够成功的操作序列 |
| LLM 闭环评测 | 固定测试集，按声明的信息权限观察 | 模型能否独立判断并执行，成功率与成本如何 |

从存档起步通过 2F，只能证明在该起点完成一次两旗运阵；不能直接证明从零可建阵、长期不亏阳光或随机条件下稳定。这里的 **F 表示旗，cs 表示百分之一游戏秒**，不要把 2F 理解成两帧。

### 如何理解这张阵图

四行陆路不能按相同的危险线处理。第二、五行的红眼会直接威胁岸路忧郁菇；第一、六行没有前置常驻植物，主要风险是僵尸穿过输出区后进家。第三、四行的前场忧郁菇还需要防啃食、蹦极等威胁。判断“谁最靠左”时，必须同时考虑其所在行、攻击目标与剩余可承受伤害。

后场伞与前场水曾之间有明显距离，不能假定两个伞保护了所有常驻植物。看见蹦极目标时，要核查实际保护范围及灰烬处理安排。

## 3. 运阵卡组：每张卡都要有明确职责

官方示例选择以下十张卡。它们是**运阵卡组**，没有重建忧郁菇、双子向日葵、伞的完整组件。[选卡与主流程源码](https://github.com/vector-wlc/AsmVsZombies/blob/c42676c269b5b482a1eb9203a5b979e9d8a2a5c7/tutorial/scripts/liang_yi/liang_yi.cpp)

| 卡片 | 首要职责 | 需要同时检查的条件 |
|---|---|---|
| 荷叶 | 提供水路冰、核的落点 | 卡片冷却、格子占用、核坑；不能先花掉后才发现核无处种 |
| 南瓜头 | 修复常驻植物的保护层 | 当前血量、受击速度、下一次补套能否赶上 |
| 寒冰菇 | 全场控制，延长输出与控丑窗口 | 生效时刻；落点能否存活到生效 |
| 模仿寒冰菇 | 与原冰交替承担控制 | 变身时间与落点保护；不能照搬原冰的种植时刻 |
| 毁灭菇 | 大范围高伤害、整合当前压力 | 覆盖边界、荷叶、核坑与后续使用计划 |
| 樱桃炸弹 | 处理一个半场的重点压力 | 最左威胁能否被覆盖，另一半场由谁承担 |
| 火爆辣椒 | 清一整行、配合樱桃／核处理漏怪 | 选哪一行、何时生效、是否与其他伤害重叠 |
| 倭瓜 | 针对局部关键目标补伤害 | 实际会锁到哪只僵尸；前方杂兵可能改变结果 |
| 小喷菇 | 低成本垫材，诱发巨人锤击以争取时间 | 是否诱发了有效动作，是否刚落地便被碾掉或炸掉 |
| 三叶草 | 处理气球、按需清雾；有时兼任临时垫材 | 气球离失败边界的距离、卡片冷却与经济成本 |

“蓝冰”通常指原版寒冰菇，“白冰”指模仿寒冰菇。本文中的“灰烬”主要指樱桃、辣椒、核，倭瓜作为局部伤害单独讨论；“垫材”是为了拖延或诱发动作而临时种下的植物。

“IO”在下面指阵型常驻植物提供的持续输出。学习阶段可以先不用复杂轨道术语，直接问：**在僵尸造成不可接受的破坏前，剩下的持续输出能否打死它？**

## 4. 一次观察应该怎样做

下面是本文建议的决策顺序，适合手动暂停练习，也适合 LLM 的结构化观察。

1. **找最近的失败事件。** 不是单看横坐标，而是找气球进家、巨人命中核心、水曾南瓜被啃穿、蹦极抓走核心等事件谁先发生。
2. **检查已经承诺的伤害与控制。** 哪个樱桃已经种下、哪行辣椒即将生效、冰什么时候发动、倭瓜正在追谁。已经种下的植物不能当成“还没做任何事”。
3. **检查卡片与落点。** 卡是否可用、阳光是否够、格子是否有核坑或冰道、所需荷叶是否可用、落点是否会先被炸掉或碾掉。
4. **选择最小的有效干预。** 能用一个有效垫材解决，就不急着把两张灰烬一起交掉；已无安全窗口时，应及时交关键卡，避免为了省阳光直接丢核心。
5. **给下一次观察设触发条件。** 到冰生效、灰烬爆炸、僵尸接近危险区域、卡片恢复或波次改变时重新观察。

LLM 观察可以包含以下信息；这一列表是接口设计建议，并不表示当前 AvZ 已经把它们封装成一个现成对象。

| 类别 | 最少应提供的内容 |
|---|---|
| 时间 | 本两旗周期编号、当前波、波内 cs、单调递增的游戏时钟 |
| 卡片 | 卡名、剩余冷却、可用性、实际费用、当前阳光 |
| 常驻植物 | 稳定 ID、种类、行列、血量、保护层、是否被抓取 |
| 重点僵尸 | 稳定 ID、种类、行路、坐标、血量、状态、锤击／投掷／爆炸等进度 |
| 场地 | 核坑及剩余时间、冰道、临时荷叶、可种植性 |
| 待生效动作 | 种植成功帧、预计生效帧、目标或预计覆盖范围 |
| 观察权限 | 是否给出雾后目标、精确冷却、精确冻结倒计时等隐藏信息 |

注意：若只给截图，就不能把内存读取的雾后坐标偷偷补进观察；若明确允许全状态，可以用这些数据降低视觉识别负担。两种成绩应分开报告。

## 5. 核心处理：怎样把资源花在会破阵的地方

### 5.1 红眼：区分“必死但还没死”与“真的会破阵”

最常见的浪费是看到靠左红眼就无条件砸倭瓜，而它原本已经会被忧郁菇击杀。相反，只看损伤贴图就断言它必死，也可能漏掉速度、冻结、攻击间隔和输出范围的影响。

本文建议用一个保守判断过程：先估计它到攻击／进家边界还剩多少游戏时间，再估计这段时间内可获得的持续伤害，最后计入已承诺的灰烬。存在较大不确定性时，把不确定性写进决策，优先用能够延长判断窗口的低成本动作。

官方示例的 `IsGigaIoDead` 是近似计算，并且作者在代码中明确说明参数有经验调整、未完整计算垫材影响。它还读取了精确冻结倒计时。因此可以把它当基线特征或研究对象，不应把返回值当必然正确的生死判决。[判定代码](https://github.com/vector-wlc/AsmVsZombies/blob/c42676c269b5b482a1eb9203a5b979e9d8a2a5c7/tutorial/scripts/liang_yi/judge.h)

练习顺序建议是：先只处理单路单红眼；再加入同路多个红眼；最后才练两条岸路同时受压。每次记录垫材是否真正诱发了一次锤击，以及它换来了多少有效输出时间。

### 5.2 垫材：种下不等于拖住

种小喷菇前，至少确认三件事：目标会与它发生互动、它不会先被其他机制瞬间清除、拖延足以改变结局。小丑爆炸、冰车碾压和巨人正在结算的锤击，都会让“合法落地”变成“没有收益”。

不要把“卡冷却好就种”当通用规则。下一张冰／三叶草可能还需要同一个格子；一次无效垫材也可能堵住灰烬落点。逐帧控制最值得优化的是动作的有效性，而不是动作数量。

临时用冰或三叶草垫巨人时，先保证其主功能。气球已经危险，就不能为了等一个漂亮的垫材位置而延误吹气球；冰承担控丑时，也不能无限等待更优落点。官方教程明确讨论了这种职责优先级。[官方两仪教程](https://github.com/vector-wlc/AsmVsZombies/blob/c42676c269b5b482a1eb9203a5b979e9d8a2a5c7/tutorial/29_liang_yi.md)

### 5.3 樱桃、辣椒、倭瓜要一起分配

把它们当作一份预算安排，分别负责不同压力：樱桃承担一个半场，辣椒承担重点单行，倭瓜补仍未解决的局部威胁。分配时按“不能等待的目标”优先，其次才看一次能打到多少只。

一个可用于暂停练习的情形：上岸路红眼即将碰到核心，下边路也有前移目标。先确认哪个目标能用持续输出加垫材处理，再决定樱桃保哪个半场、辣椒分给哪条边路。若倭瓜将被前方橄榄引走，就不能把它的伤害算给后方红眼。

这是判断流程示例，并非固定应对口诀。不同血量、距离、现有冻结状态和卡片冷却可能得出相反的分配。

### 5.4 核不是全屏清除，落点会决定漏哪边

毁灭菇承担大范围伤害，但它仍有覆盖边界。越靠右的核、不同水路的核，会让边路快怪的处境不同。因此决定核点时，要一起看最左橄榄、上下半场压力、前一次辣椒所在行和下一次核的可用位置。

核坑也是跨波、跨两旗周期的资源。为每个候选格记录最近一次起爆时刻和剩余不可种植时间，安排当前核时顺带检查之后至少两次核。不要只验证“这一颗现在能种”。

### 5.5 补套与铲套：保护层需要独立控制

南瓜维修优先级应由“剩余安全时间”决定：同样血量，正在被密集啃食的南瓜通常比暂时无人攻击的更急。岸路核心曾的保护层尤其值得优先观察。

铲套是高级细节：某些巨人攻击边界下，及时只铲南瓜可以改变受击关系，但结果还取决于攻击进度、相邻垫材及对象关系。不能概括成“举锤就铲套”，更不能误铲主植物。建议单独做一段逐帧练习，确认执行器的“只铲南瓜”参数与实测结果，再纳入正式策略。官方处理代码包含这类特殊判断，而不是只按一个距离阈值操作。[植物操作源码](https://github.com/vector-wlc/AsmVsZombies/blob/c42676c269b5b482a1eb9203a5b979e9d8a2a5c7/tutorial/scripts/liang_yi/processor.h)

## 6. 威胁速查表

| 对象／事件 | 需要观察什么 | 处理方向 | 常见失误 |
|---|---|---|---|
| 红眼巨人 | 行路、剩余血量、冻结、锤击、已承诺伤害 | 有效垫材、倭瓜、半场／单行灰烬 | 把持续输出估算当保证；对多个目标重复花卡 |
| 普通巨人 | 即将攻击的植物、投掷及当前阶段 | 同样按实际破坏风险判断 | 观察器只筛红眼，完全漏掉其他巨人 |
| 小丑 | 爆炸状态、邻近灰烬／垫材、控丑是否按时生效 | 用冰与持续输出维持安排，避开危险种植窗口 | 只关心会不会炸核心，忽略刚种的樱桃或垫材 |
| 冰车 | 行路、碾压区域、冰道、可用落点 | 换落点、换行处理，核查种植是否合法 | 小喷刚种就没了；灰烬计划建立在不可种的格子上 |
| 橄榄 | 最左目标、边路压力、核覆盖边界 | 提前分配辣椒／樱桃／倭瓜，必要时改变核计划 | 以为核必定覆盖上下两条边路所有目标 |
| 气球 | 最靠左气球、三叶草冷却、可安全生效的落点 | 在失败前可靠吹除，尽量兼顾清雾与垫材收益 | 为省一次三叶草或等待垫材时机而漏气球 |
| 蹦极 | 目标格、伞的覆盖、实际下落／抓取状态 | 核查旗帜波安排，保护未被伞覆盖的核心 | 认为有伞便完全不需要看第六列水曾 |
| 矿工、小鬼、舞王衍生单位等 | 后场／新出现实体与南瓜损耗 | 纳入观察和事件日志，按当前风险处理 | 只看初始出怪表，漏掉衍生生成与后场压力 |
| 水路杂兵 | 水曾保护层损耗、积压数量 | 补套、检查本波控制与清场是否失效 | 无红眼就长时间不看水路 |

本表是完整观察器的建议。官方演示脚本重点缓存红眼、小丑、冰车、气球，并不代表其他僵尸永远无需观察。

## 7. 一波如何推进，以及怎样读懂示例时间表

### 7.1 先用状态循环，再学习节奏

对初学者，建议每波按以下流程练习：

1. 刷新时确认波号变化、上波残留以及当前卡片；记录实际刷新时刻。
2. 检查本波冰的可用性和安全落点，把目标生效时刻与种植时刻分开。
3. 冰生效前后重新判断四条陆路压力，并确定樱桃、辣椒、倭瓜的分工。
4. 中段处理必要垫材、气球与补套；持续修正“此目标是否仍需主动伤害”的判断。
5. 灰烬即将生效时，避免对同一目标重复提交昂贵动作；到生效事件后确认实际击杀与漏怪。
6. 波次改变时重新规划，不把旧波的剩余秒数直接当作新波时间。

AvZ 时间单位为 `(波,cs)`，1cs 对应 0.01 游戏秒，1–20 波以本波僵尸生成时刻为基准。真实经过一分钟并不等于推进一分钟游戏时间；TAS 暂停期间游戏时钟应停止。[AvZ 时间体系](https://github.com/vector-wlc/AsmVsZombies/blob/c42676c269b5b482a1eb9203a5b979e9d8a2a5c7/tutorial/09_time.md)

### 7.2 官方示例的调度：用于分析与建立基线

以下是源码实际登记的主要调用，**不是保证成功的推荐轨道**。很多函数会等待冷却、可种植性或危险窗口，因此登记时刻不等于实际种植成功时刻。脚本初始化还会在 `(6,9)` 放一个倭瓜；这是该示例起手的一部分，不能只抄后面的循环而忽略初始动作。

| 波次 | 波内调用 | 说明 |
|---|---|---|
| 每一波 1–20 | `480cs` 调用用冰逻辑 | 模仿冰可直接种下，原冰分支另延迟 `320cs`；设计目标约在 `900cs` 生效，实际须验收 |
| 每一波 1–20 | `2000cs` 暂停部分自动决策 | 暂停的是脚本处理器的部分工作，不是冻结游戏 |
| 1、3、5、7、9、10、12、14、16、18 | `900cs` 分配樱桃／辣椒方向，`2200cs` 尝试樱桃 | 方向取决于局面；不能把固定时间表理解成固定坐标表 |
| 2、4、6、8、11、13、15、17、19、20 | `266cs` 尝试辣椒，`2200cs` 尝试核 | 辣椒与上一波的分配相关 |
| 9 | `2500cs` 额外调用辣椒与冰 | 中场转场需额外观察 |
| 10 | `295cs` 额外用核 | 源码注释为核处理蹦极 |
| 12 | `1000cs` 决定后续一个核的水路 | 与辣椒方向联动 |
| 19 | `2500cs` 额外调用冰 | 收尾转场 |
| 20 | `0cs` 分配方向；`295cs` 在 `(3,4)` 荷叶上放樱桃；`2500cs` 再调用冰 | 源码注释为樱桃处理蹦极；另保留该波常规调用 |

上表不是说明所有波自然长度固定为 2500cs。自然刷新受游戏机制和本波战况影响；也不能通过强制设置波长，把未解决的自然刷新问题隐藏起来。额外用冰会改变交替状态，不能简单写死“所有奇数波永远白冰、偶数波永远蓝冰”。[主流程](https://github.com/vector-wlc/AsmVsZombies/blob/c42676c269b5b482a1eb9203a5b979e9d8a2a5c7/tutorial/scripts/liang_yi/liang_yi.cpp)

## 8. 阳光与补阵：活下来以后，还要检查能否继续

运阵经济用实测账本更可靠。本文建议每波和每个两旗周期记录：

`期末阳光 = 期初阳光 + 实际收集收入 − 实际种植支出`

统计支出时按用途分为计划灰烬、正常补套、应急三叶草／垫材、补阵等；同时记录最低阳光和关键卡因阳光不足失败的次数。不要把产出的全部阳光自动当成已经收集的收入。

建议从三个问题分析亏损：

- 是本测试出怪本来就消耗较大，还是多次樱桃、辣椒、倭瓜在同一目标上重叠？
- 是南瓜正常消耗，还是控场延误使持续啃食显著增加？
- 是吹气球所需，还是为了观察方便反复清雾消耗三叶草？

一次困难局亏阳光并不直接否定整个阵型；一次阳光回升也不证明所有条件都能无限维持。真实玩家的一次自然出怪两旗展示就明确将南瓜抗压、阳光把控和灰烬分配列为不同难点，适合观察其操作取舍。[谔虺的慢速自然出怪 2F 展示](https://www.bilibili.com/video/BV1ha411o7Sv/)

运阵卡组缺少核心重建组件，所以建议正式评测同时记录两项结果：**是否游戏失败**、**是否核心破阵**。例如丢一颗忧郁菇但强行拖到选卡界面，应记作核心损失，不能只写“通过”。练习阶段可允许下一次选卡尝试补阵，但要记录新增卡组与额外阳光，作为另一种任务。

## 9. 从零建阵应怎样另开一条练习路线

本文没有核实一份可以直接照抄的全程建阵时刻表，下面只给出建阵学习的组织方法，不编造前几旗的精确落点与时机。

先看作者发布的开局录像，把它拆成“经济建立、后场保护、四个常驻输出点建立、撤除过渡植物、切换运阵卡组”几个阶段。每个阶段记录开始条件、临时植物、主阵完成度和阳光底线；录像标题中的“开局”也应以实际播放内容确认，不根据标题推断每一步。[KallBet佬王《九章阵华录—主 HA—雾夜两仪无炮【开局】》](https://www.bilibili.com/video/BV1xW411e7Yg/)

对 LLM 项目，建议先完成已有阵型运阵，再单独评测建阵。若先用修改器摆好阵型，应如实命名为“人工构造的成型起点”；这很适合测策略，但不能当成模型自行建阵的成绩。

## 10. 手动、TAS、LLM 的练习路径

以下是本文建议的分阶段路径，门槛可按实际难度调整。

| 阶段 | 练什么 | 通过时应能展示的证据 |
|---|---|---|
| 1. 读阵 | 认全 12 主植物格、卡片职责、四条陆路不同危险线 | 对暂停局面说明最近风险与下一张关键卡 |
| 2. 单项动作 | 有效垫红眼、准确倭瓜、补套、吹气球、核落点 | 逐帧片段与前后状态，能解释成功或失败原因 |
| 3. 两波配合 | 冰、樱桃、辣椒、核之间的接续 | 不重叠浪费，记录实际生效时间与残留目标 |
| 4. 一个两旗周期 | 1–20 波完整运阵，包括中场和收尾 | 核心损失、阳光变化、用卡数量、失败事件 |
| 5. 跨周期连续 | 不清除核坑等真实残留，继续下一次选卡周期 | 首轮收尾不会破坏后续资源计划 |
| 6. 泛化 | 相同规则下换出怪条件、换初始冷却／血量 | 多个独立案例，包含失败与最差情况 |

手动练习可以先暂停分析，再恢复原速；TAS 练习可以回档对比两个动作。允许回档的成功序列与不回档的在线决策能力应分开报告。对 LLM，同样不要把搜索很多分支后选出的最好录像，计作一次不回档运行。

### LLM 执行器宜保持明确边界

可给模型提供 `observe`、`plant`、`shovel`、`advance` 这类简单操作。每次种植应返回成功／失败、实际执行帧与原因；每次推进允许在声明的关键事件上提前返回。

如果执行器会自动补套、自动吹气球或自动垫红眼，这些动作已经含有策略，应注明是“LLM＋规则辅助”。官方两仪脚本本身会自动决策，因此不能完整运行脚本后，把成功全部归给只偶尔发出指令的 LLM。

一个合适的决策记录例子是：

> 第 5 波，当前帧已确认。最紧急风险是下岸路核心受击；樱桃尚未种下，辣椒已预留上边路。选择在可用位置放倭瓜；执行后等待其锁定事件，若目标改变立即重新观察。

这类记录比只输出“种倭瓜”更便于复盘，但无需让模型每一帧写一段长文。

## 11. 失败复盘：找第一处不可挽回的变化

“第 8 波掉曾”只是结果。建议倒查导致它的第一处策略或执行错误：

| 现象 | 应倒查的数据 |
|---|---|
| 红眼砸掉岸曾 | 垫材是否生效、冻结何时结束、锤击命中帧、预计持续伤害是否高估 |
| 边路橄榄进家 | 灰烬实际覆盖、辣椒选择行、自然刷新是否改变原计划 |
| 樱桃没发挥作用 | 种植返回值、是否被小丑清除、爆炸时目标位置、是否已被其他伤害击杀 |
| 倭瓜打错目标 | 锁定目标与种植瞬间目标是否相同，附近是否存在更早触发的杂兵 |
| 水曾保护层被啃穿 | 血量曲线、上次补套、控制空窗、卡片冷却与阳光 |
| 核无法种植 | 核坑、荷叶可用性、格子占用、前一周期残留 |
| 连续亏阳光 | 各类支出、重复伤害、频繁清雾、无效垫材、过度补套 |
| 同一方案复跑不同 | 起始状态、游戏随机状态、插件、动作帧、第一处状态分叉 |

对 TAS／LLM，最低限度应保留：初始状态标识、逐条动作及实际成功帧、每波边界、僵尸生成／消失／重要状态事件、植物损失、阳光流水、少量关键状态快照。可再配低帧率视频供人观看；录像与结构化日志解决的问题不同。

## 12. 用官方示例做评测前，必须说明的条件

这部分是避免误读基线的说明，不要求额外修改游戏规则。

- **源码是接口教学示例。** 作者明确不保证成功率，主文件也说明目前不能挂机。
- **它调用 `ASetZombies`，使用默认 `AVERAGE` 模式。** 这会按给定类型构造出怪表；不仅是展示一个允许类型集合，不能直接标成完全未经干预的随机自然出怪。[接口默认值](https://github.com/vector-wlc/AsmVsZombies/blob/c42676c269b5b482a1eb9203a5b979e9d8a2a5c7/inc/avz_memory.h)
- **它直接读内存。** 包括精确冻结倒计时，信息条件强于只看原始雾夜画面。
- **一些阈值是经验参数。** 不要把危险距离、伤害近似、维修优先级偏移写成经过证明的通用常数。
- **末波核坑有已知循环问题。** 必须看跨周期表现。
- **调度不是执行成功。** 协程可能等待，动作可能因落点或资源失败，日志需要记录实际结果。

如果研究目的是让 LLM 学会运阵，最有价值的首个结果是：**在声明清楚的成型阵、观察权限、自然或指定出怪规则下，不回档完成一轮，并能用日志说明每次关键操作为何发生。** 接着再测连续周期、经济趋势与新案例；不要从一次成功录像直接跳到“已经会稳定无尽”。
